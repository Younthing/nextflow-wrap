# 在集群和云上运行

画布上的流程不改一行，就能换个地方跑：在这台电脑上、在学校或公司集群的登录节点上，或交给 AWS / Google / Azure 的批处理服务。

## 集群（经 SSH）

### 准备

1. 能免密 SSH 登录集群：在终端里 `ssh 你的用户名@登录节点` 不需要输入密码（ssh-agent 里有密钥，或在 `~/.ssh/config` 里配好）。第一次连接请先在终端里确认主机指纹。桌面版不能替你输入密码或验证码。
2. 集群上有 Nextflow 和 Java 17 以上。用 module 管理软件的集群，记下加载它们的命令，例如 `module load java/17 nextflow`。

### 添加集群

设置 →「远程集群」→「添加集群」，填写：

| 字段 | 说明 |
| --- | --- |
| 主机 | 登录节点的主机名，或 `~/.ssh/config` 里的别名 |
| 用户名、端口、私钥文件 | 可留空，留空时按 `~/.ssh/config` 和 ssh-agent |
| 集群上的基础目录 | 默认 `~/nextflow-studio`。放流程的启动目录、每次运行的文件和默认 work 目录。要在计算节点也能访问的共享盘上，空间大的 scratch 盘更合适 |
| Nextflow 命令 | 默认 `nextflow`；不在 PATH 上时填完整路径 |
| 登录后先执行 | 一行 shell 命令，启动 Nextflow 前运行，例如加载模块或激活 conda 环境 |

点「测试连接」：成功时列出基础目录的实际路径、Nextflow 和 Java 版本，以及找到的调度器（sbatch、qsub、bsub…）和运行时（apptainer、conda…）。失败时会说明原因，例如认证失败、主机名不对或网络不通。确认无误后「保存集群设置」。

### 运行

「运行设置」最上面多了「从哪里启动 Nextflow」。选中集群后：

- **任务在哪里执行**：「登录节点」直接在登录节点上跑任务，只适合很轻的流程；选 SLURM、PBS、LSF 等则由 Nextflow 在登录节点上向调度器提交作业，可以填队列和额外提交参数。
- **软件环境**：集群上通常用 Apptainer / Singularity 或 Conda；Docker 一般不可用。
- **工作目录**：填 `work` 时用「基础目录/work」；也可以填集群上别的绝对路径。
- **输入文件**：项目里的文件（如 `data/pbmc3k.h5ad`，以及工作区样本表里写的文件）在启动前自动复制到集群上的 `基础目录/projects/<项目>/`，保持相同的相对路径；大小和修改时间没变的文件不会重复上传。已经在集群上的数据直接写集群上的绝对路径或对象存储地址。通配路径（`data/*.fq`）和项目文件夹以外的路径不会上传，请改成文件夹或写集群路径。

启动后，桌面版把项目复制到集群上的 `基础目录/pipelines/<流程>`，在登录节点上用 nohup 启动 Nextflow。Nextflow 在集群上独立运行：合上电脑、断网或退出应用都不影响它。桌面版每 10 秒通过 SSH 看一次进度、任务列表和日志；重新打开应用时会接着跟踪。

在运行页：

- 「任务」里点一个任务，日志是从集群上读的。
- 运行结束后，日志、报告和结果文件会取回本机，「结果」页和本机运行一样预览。结果超过 2 GB 时留在集群上，页面会给出它在集群上的位置。
- 「停止」会让集群上的 Nextflow 取消已提交的作业再退出。
- 「从此运行恢复」在同一个集群上用 `-resume` 续跑，已完成的步骤直接用缓存。

运行列表和运行页的「运行环境」一栏会写出集群名，例如「实验室集群 · SLURM」。

### 常见问题

| 现象 | 处理 |
| --- | --- |
| 测试连接提示认证失败 | 先在终端里确认 `ssh -o BatchMode=yes 主机 true` 能成功；需要时在「私钥文件」里选密钥 |
| 提示「主机密钥未确认」 | 在终端里 ssh 一次并输入 yes |
| 在集群上找不到 nextflow | 「登录后先执行」里加载它，或在「Nextflow 命令」里填完整路径 |
| 提示找不到 sbatch | 这台登录节点上没有所选调度器；换调度器，或选「登录节点」 |
| 运行失败，说输入文件不存在 | 参数里的路径要写集群上的路径 |
| 长时间连不上集群 | 网络或 VPN 断开 30 分钟后桌面版停止跟踪，运行标为失败；Nextflow 可能仍在集群上运行，日志在 `基础目录/runs/<运行 id>/` |

## 云端批处理

AWS Batch、Google Batch、Azure Batch 和 Kubernetes 由这台电脑上的 Nextflow 直接提交，不经过集群。凭据在 设置 →「偏好」→「云端凭据」：

| 云 | 填写 |
| --- | --- |
| AWS | AWS profile（`~/.aws/config` 里的名字）或 Access Key ID + Secret Access Key；区域 |
| Google | 服务账号 JSON 文件；已经 `gcloud auth application-default login` 过可以留空 |
| Azure | Batch 账户名和密钥、存储账户名和密钥 |

密钥和 AI 助手的 API key 一样只写不读：页面只显示「已保存」，桌面版用系统钥匙串保护的密钥加密保存。保存后重启应用生效。终端里已经设置的同名环境变量优先，页面上会注明。

在「运行设置」里选对应的执行器，填作业队列、项目等设置，工作目录写成 `s3://`、`gs://` 或 `az://` 开头的地址。
